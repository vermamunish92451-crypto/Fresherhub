Healthcare Management System

Complete Interview Questions & Answers

Project: AI-Powered Disease Prediction & Recommendation System

1. Project Overview & Basic Questions
Q1: What is this project about?
Ans: This is an AI-powered Healthcare Management System that predicts diseases based on patient symptoms using Machine Learning (Random Forest algorithm). It provides medicine recommendations, diet plans, and workout routines for 41 different diseases.
Q2: What problem does this project solve?
Ans: It helps users get preliminary health assessment based on their symptoms. It provides instant disease prediction, medicine suggestions, diet plans, and workout routines - acting as a first-level health advisor before consulting a doctor.
Q3: What is the accuracy of your model?
Ans: The model achieves 99.5% accuracy on the test dataset. This high accuracy is due to the well-structured symptom-disease mapping and the Random Forest algorithm with 200 decision trees.
Q4: How many diseases and symptoms does your system cover?
Ans: The system covers 41 diseases across multiple categories (Respiratory, Cardiovascular, Gastrointestinal, etc.) and 130+ symptoms in the database.
Q5: What is the tech stack used in this project?
Ans: Python (main language), SQLite (database), Scikit-learn (ML), Pandas & NumPy (data processing), Matplotlib & Seaborn (visualization), Streamlit (web app), Power BI (dashboard), FPDF2 (PDF generation).
2. Machine Learning Questions
Q6: Which ML algorithm did you use and why?
Ans: Random Forest Classifier with 200 decision trees. Chosen because: (1) Handles multi-class classification well, (2) Robust against overfitting, (3) Works well with categorical binary features (symptoms), (4) Provides feature importance, (5) High accuracy with minimal tuning.
Q7: How does Random Forest work?
Ans: Random Forest creates multiple decision trees during training. Each tree is trained on a random subset of data and features. For prediction, all trees vote and the majority class is chosen. This reduces overfitting and improves accuracy compared to a single decision tree.
Q8: What is the input to your ML model?
Ans: Input is a binary vector of size 130 (number of symptoms). Each position represents whether a symptom is present (1) or absent (0). For example, if user selects "fever" and "headache", the vector will have 1 at those positions and 0 elsewhere.
Q9: How did you handle overfitting?
Ans: (1) Used Random Forest instead of single Decision Tree, (2) Set n_estimators=200 for better generalization, (3) Used class_weight='balanced' for imbalanced classes, (4) Applied train_test_split with 80-20 ratio, (5) Used stratify=y for balanced distribution.
Q10: What is feature engineering in your project?
Ans: Feature engineering involves converting raw symptoms into a binary feature vector. Each symptom becomes a feature (column) with value 1 if present, 0 if absent. This one-hot encoding approach works well for the symptom-disease classification problem.
Q11: How did you split the data for training?
Ans: Used train_test_split with 80% training and 20% testing data. Applied stratify=y to maintain equal distribution of diseases in both sets. Random_state=42 ensures reproducibility.
Q12: What is the role of n_estimators in Random Forest?
Ans: n_estimators specifies the number of decision trees in the forest. More trees generally improve accuracy but increase computation time. I used 200 trees which gives optimal balance between accuracy and performance.
Q13: How does the model predict top 3 diseases?
Ans: Using predict_proba() method which returns probability for each class. I sort probabilities in descending order and pick top 3. This gives users alternative possibilities if the top prediction doesn't match their expectation.
3. Database & SQL Questions
Q14: What database did you use and why?
Ans: SQLite because: (1) Serverless - no setup required, (2) Single file database - easy to share, (3) Perfect for small to medium applications, (4) Built-in Python support, (5) ACID compliant for data integrity.
Q15: How many tables are in your database?
Ans: 8 tables: (1) patients - user registration, (2) diseases - disease info, (3) symptoms - symptom list, (4) disease_symptoms - mapping table, (5) medicines - prescriptions, (6) diet_plans - nutrition info, (7) workout_plans - exercise routines, (8) predictions - prediction logs.
Q16: What is the relationship between tables?
Ans: Many-to-many relationship between diseases and symptoms via disease_symptoms table. One-to-many: one disease has many medicines, diet plans, and workout plans. Foreign keys ensure referential integrity.
Q17: Why did you use foreign keys?
Ans: Foreign keys ensure data integrity by preventing orphaned records. For example, a medicine record cannot exist without a valid disease_id. This maintains consistency and prevents data corruption.
Q18: What is PRAGMA foreign_keys?
Ans: PRAGMA foreign_keys = ON enables foreign key constraint enforcement in SQLite. By default, SQLite doesn't enforce foreign keys. This command ensures that all foreign key relationships are properly maintained.
4. Python & Streamlit Questions
Q19: Why did you choose Streamlit for the frontend?
Ans: Streamlit because: (1) Pure Python - no HTML/CSS/JS needed, (2) Rapid prototyping, (3) Built-in widgets (buttons, sliders, etc.), (4) Easy to deploy, (5) Great for ML project demos, (6) Automatic responsive design.
Q20: What is @st.cache_resource and @st.cache_data?
Ans: @st.cache_resource caches expensive resources (like ML model, database connections) that are shared across all users. @st.cache_data caches function results (like dataframe queries) for each user session. Both improve performance by avoiding recomputation.
Q21: How does Streamlit handle state management?
Ans: Streamlit uses st.session_state for persistent state across reruns. Variables like logged_in, dark_mode, chat_history are stored in session_state and persist during the user's session. This enables features like login, dark mode toggle, and chat history.
Q22: What is pickle and why did you use it?
Ans: Pickle is Python's serialization library used to save/load Python objects. I used it to save the trained ML model, symptom list, and accuracy score into a single .pkl file. This allows quick model loading without retraining.
Q23: What are the security concerns with pickle?
Ans: Pickle can execute arbitrary code when loading untrusted files. Never load pickle files from unknown sources. For production, use safer alternatives like joblib or ONNX format. In this project, since we control the model, pickle is acceptable.
5. Features & Functionality Questions
Q24: Explain the complete workflow of disease prediction.
Ans: (1) User selects symptoms from multiselect dropdown, (2) Binary vector created (130 dimensions), (3) Random Forest model predicts probabilities for 41 diseases, (4) Top 3 predictions shown with confidence %, (5) Disease details fetched from database, (6) Medicine, diet, workout recommendations displayed, (7) Prediction logged to database.
Q25: How does the BMI Calculator work?
Ans: BMI = Weight(kg) / Height(m)². Based on BMI value: <18.5 = Underweight, 18.5-24.9 = Normal, 25-29.9 = Overweight, >=30 = Obese. Health score calculated based on how far BMI is from normal range.
Q26: How does the Disease Comparison feature work?
Ans: User selects two diseases from dropdowns. System fetches details for both from database and displays side-by-side comparison including: description, severity, category, medicines, diet plans, and workout routines.
Q27: How does the PDF generation work?
Ans: Using FPDF2 library, I create a PDF with: header (project name), date, symptoms list, predicted disease with confidence, severity, description, medicines, diet plan, workout plan, and disclaimer. The PDF is generated in-memory and provided as download button.
Q28: How does the chatbot work?
Ans: Rule-based chatbot using keyword matching. User input is converted to lowercase and matched against predefined keywords (fever, headache, diet, etc.). Corresponding response is returned. Chat history maintained in session_state for conversation continuity.
Q29: How does dark mode work?
Ans: Using st.session_state.dark_mode boolean toggle. When enabled, injects CSS that changes background to dark colors (#0e1117) and text to light colors (#fafafa). When disabled, light theme CSS is applied.

7. Code-Specific Questions
Q35: Explain the predict() function.
Ans: Takes model, symptom_list, and selected symptoms. Creates binary vector (1 if symptom selected, 0 otherwise). Uses predict_proba() to get probabilities for all 41 diseases. Returns top prediction, confidence, and top 3 predictions sorted by probability.
Q36: What does 'stratify=y' do in train_test_split?
Ans: Ensures that both training and testing sets have approximately the same percentage of samples of each disease class. This prevents bias where some diseases might be overrepresented in training and underrepresented in testing.
Q37: Why use matplotlib.use('Agg')?
Ans: 'Agg' is a non-interactive backend for matplotlib. Since Streamlit runs on a server without display, we need a backend that can generate images without showing them on screen. This prevents matplotlib from trying to open GUI windows.
Q38: What is the purpose of plt.close()?
Ans: Closes the matplotlib figure to free memory. Without this, each chart would accumulate in memory causing memory leaks. Important in Streamlit since charts are regenerated on each rerun.
Q39: How does st.multiselect work?
Ans: Creates a dropdown where users can select multiple options. Returns a list of selected items. Used for symptom selection where users can choose multiple symptoms from the 130+ available options.
Q40: What is unsafe_allow_html=True?
Ans: Streamlit sanitizes HTML by default for security. This parameter tells Streamlit to render raw HTML content. Used for custom styled components like disease boxes, medicine cards, etc. Must be careful with user-provided content to prevent XSS attacks.
8. Scenario-Based Questions
Q41: What if a user enters symptoms that don't match any disease?
Ans: The model still predicts the closest matching disease based on symptom similarity. Top 3 predictions shown help user identify if any matches. A warning message is shown advising to consult a doctor for accurate diagnosis.
Q42: How would you handle 1000+ concurrent users?
Ans: (1) Use caching (@st.cache_resource) for model loading, (2) Add database connection pooling, (3) Use Redis for session management, (4) Deploy on multiple instances with load balancer, (5) Use async operations for database queries.
Q43: What if the model predicts wrong?
Ans: System shows disclaimer that it's AI-based prediction. Top 3 predictions give alternatives. Prediction is logged for future analysis. Can retrain model with corrected data. User advised to consult doctor for actual diagnosis.
Q44: How would you add new diseases to the system?
Ans: (1) Add disease to diseases table, (2) Map symptoms in disease_symptoms table, (3) Add medicines, diet, workout plans, (4) Retrain the model with updated dataset, (5) Save new model as pkl file. No code changes needed - just data updates.
Q45: How would you make this project production-ready?
Ans: (1) Add user authentication, (2) Implement rate limiting, (3) Add input validation, (4) Use PostgreSQL instead of SQLite, (5) Add logging and monitoring, (6) Implement CI/CD pipeline, (7) Add unit tests, (8) Use Docker for containerization, (9) Add API endpoints.
